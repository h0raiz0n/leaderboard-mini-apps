# ♠️ Poker Admin — Система учёта покерного клуба

Google Apps Script (V8) проекта автоматизации покер-клуба:
лидерборд, статистика, Telegram-уведомления и API для Telegram Mini App.

---

## 📁 Структура проекта

| Файл | Роль |
|------|------|
| `appsscript.json` | Манифест (часовой пояс, права, web-app) |
| `.clasp.json` | Конфигурация деплоя через CLASP |
| `Config.js` | **Единый источник правды**: форматы, очки, формы, таблицы, утилиты |
| `Normalizer.js` | **Единый канал нормализации** строк форм → `DB_Results` |
| `Leaderboard.js` | Движок лидерборда (месяц / всё время) + публикация |
| `Backfill.js` | Аудит и бэкфилл исторических данных |
| `Analytics.js` | Статистика за всё время, зал славы, JSON-эндпоинт `doGet` для Mini App |
| `TelegramNotifier.js` | Уведомления в Telegram |
| `Setup.js` | Перенос секретов в скриптовые свойства (безопасность) |
| `Formatting.js` | Условное форматирование лидерборда (A3) |
| `Code.js` | Меню, `syncAll`, `processFormSubmit`, `takeSnapshot` |

## 🗺️ Три ключевых направления (стратегия)

### 1. Оптимизация нормализации
**Проблема:** логика форматов дублировалась; счётчик игр дилера считался из
`DB_Results`, из-за чего «пустые» игры терялись и всегда показывалось «1-я игра».

**Решение:**
- Все правила (места/очки/нокауты) вынесены в `Config.js` (один источник правды).
- `Normalizer.js` — единственная функция `normalizeFormRow()`, которая превращает
  строку формы в записи `DB_Results`. Используется **и для live-событий, и для бэкфилла**.
- Счётчик игр дилера теперь считает по **сырым листам форм** (а не по `DB_Results`),
  поэтому «пустые» игры тоже учитываются. Баг «всегда 1-я игра» исправлен.

### 2. Бэкфилл исторических данных
**Проблема:** месяцы сырых данных лежат в листах-приёмниках, но не попадают в
`DB_Results` → не видно в лидерборде/статистике.

**Решение:** `Backfill.js`
- `auditRawData()` — безопасный аудит структуры сырых листов (ничего не меняет).
- `backfillHistoricalData()` — идемпотентный, дозированный перенос порциями.
  - **Идемпотентность:** детерминированный `gameId` (лист+дата+timestamp+строка),
    повторный запуск не создаёт дублей.
  - **Дозированность:** обрабатывает `BACKFILL_CHUNK` (100) игр за запуск,
    прогресс хранится в скриптовых свойствах. Запускайте повторно до «0 обработано».

### 3. Telegram Mini App + аналитика
**Решение:** `Analytics.js`
- `computeAllTimeStats()` — полная статистика игроков за всё время.
- `computeHallOfFame()` — зал славы победителей (1 место) любых форматов.
- `doGet(e)` — **JSON-эндпоинт** для Mini App (`?type=leaderboard|halloffame|current`).
- `calculateLeaderboardAllTime()` — выгрузка статистики в лист `AllTimeStats`.

## 🚀 Деплой

### Подготовка
1. Установите `clasp` и войдите:
   ```bash
   npm i -g @google/clasp
   clasp login
   ```
2. Свяжите с проектом (id уже в `.clasp.json`):
   ```bash
   clasp pull
   ```
3. Загрузите изменения:
   ```bash
   clasp push
   ```

### Настройка секретов (безопасность)
Секреты (токен бота, chat-id) **не хранятся в коде** — они читаются из
скриптовых свойств (`PropertiesService`). Задайте их один раз:

```bash
setSecret("TELEGRAM_BOT_TOKEN", "ваш_токен")   # в редакторе Apps Script
setSecret("TELEGRAM_CHAT_ID", "ваш_chat_id")
```

`setupSecrets()` покажет, какие секреты установлены, а какие нужно добавить,
и подтянет `PUBLIC_SPREADSHEET_ID` из `Config.js`. Проверить результат можно
через `showConfiguredSecrets()` (токен маскируется).

### Триггеры (обязательно)
В редакторе Apps Script создайте:
- `processFormSubmit` → по отправке форм (onFormSubmit) для листов
  `Data`, `MTT`, `Mystery`. Задача триггера — брать новую строку и нормализовать её.
- `takeSnapshot` → по таймеру (например, еженощно) для фиксации позиций.
- (опц.) повторите `backfillHistoricalData` через таймер, пока не закончится история.

## 🕘 Пошаговая инструкция по бэкфиллу истории

1. **Снапшот-резервная копия** `DB_Results` (отдельный архивный лист/копия файла).
2. Запустите **`auditRawData()`** — проверьте, что колонки сырых листов
   совпадают с ожидаемыми (дилер в кол.3, места с кол.4 по счёту, нокауты для
   Mystery 7-я и 8-я колонки). Если структура другая — скорректируйте `Config.js`.
3. Запустите **`backfillHistoricalData()`**. Повторяйте, пока сообщение не покажет
   «0 обработано» — это значит, вся история перенесена.
4. Запустите **`calculateLeaderboardAllTime()`** — появится лист `AllTimeStats`.
5. Проверьте выборочно, что сырые строки ↔ записи `DB_Results` бьются 1:1.
6. Если стряслось — `resetBackfillCursors()` для полного перезапуска.

> При переезде в продакшн: убедитесь, что `TELEGRAM_BOT_TOKEN`,
> `TELEGRAM_CHAT_ID` и `PUBLIC_SPREADSHEET_ID` заданы в скриптовых свойствах
> (см. `Setup.js`). В `Config.js`/`TelegramNotifier.js` секретов нет —
> только публичные ссылки/ID.

## 🕹️ Telegram Mini App

1. Разверните скрипт как **Web App** (Deploy → New deployment → Web app):
   - Execute as: **Me (user deploying)**
   - Who has access: **Anyone**
2. Копируйте URL `/exec` в переменную `TELEGRAM_MINI_APP_URL`
   в `TelegramNotifier.js` (и в `appsscript.json`).
3. Соберите фронтенд Mini App на Telegram, который загружает JSON:
   - `/exec?type=leaderboard` — лидерборд за всё время
   - `/exec?type=halloffame` — зал славы
   - `/exec?type=current` — лидерборд текущего месяца
4. Зарегистрируйте Mini App у BotFather и укажите URL фронтенда.

## 🎨 Направление А — система лидерборда

- **A1. Оптимизация** — `computeAllTimeStats` кэшируется (CacheService),
  тренды считаются относительно вчера (снапшоты по дням).
- **A2. Тренды** — `takeSnapshot` теперь хранит историю по датам (без дублей
  за один день); тренды в лидерборде сравнивают текущее место с вчерашним.
- **A3. Оформление** — `applyLeaderboardFormatting()` раскрашивает лидерборд:
  топ-3 (золото/серебро/бронза), зебра строк, подсветка трендов и рангов.
  Запуск в меню: «🎨 ОФОРМИТЬ ЛИДЕРБОРД».

## 🔧 Поддержка и расширение

- **Изменить очки/места** → правьте только `Config.FORMATS`.
- **Добавить формат** → добавьте запись в `Config.FORMATS` + лист-приёмник.
- **Инкрементальный расчёт с дельтой** (по-настоящему накапливаемый кэш очков):
  отдельная задача; при текущих объёмах полный пересчёт в `computeLeaderboardRows`
  выполняется за миллисекунды и не является узким местом.

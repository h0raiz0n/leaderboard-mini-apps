## 📌 Архитектурный контекст и фундаментальные принципы системы

### 1. Архитектура и стек
* **Frontend**: Vanilla JS (ES6+), CSS3 Variables, PWA / Service Worker (`sw.js`).
* **Клиенты**:
  * **ТВ-терминал** (`tv/`): Информационное табло для ТВ-экранов в клубе (Smart TV LG webOS, Samsung Tizen, Android TV, mini-PC).
  * **Пульт дилера** (`dealer/`): Мобильное PWA / Telegram WebApp для управления таймером стола.
  * **Telegram-бот** (`api/dealer-bot.js`): Vercel Serverless Function для пушей и авторизации.
* **Шина синхронизации**: Firebase Realtime Database (GCP `europe-west1`).
* **Бэкенд аналитики и истории**: Google Apps Script Web App (таблицы Google Sheets).
* **Хостинг**: Vercel Production (автодеплой по пушу в `main`).

---

### 2. ⚡ Железные архитектурные законы (Нерушимые правила!)
1. **Принцип «Единственного Писателя» (Single Writer Principle):**
   * **ТВ — это 100% пассивный терминал-отображатель.** ТВ **НИКОГДА** не вызывает `.set()`, `.update()` или `syncTableAutoProgression()` в Firebase. ТВ только слушает и визуализирует.
   * Никаких гонок двух устройств! Изменять состояние стола имеет право **только пульт дилера**.
2. **Детерминированное чистое время (Pure Time Math):**
   * Таймер — это чистая математическая функция от момента старта и пауз, а не мутабельный счётчик с десятком флагов.
3. **Защита от спящего смартфона (Wakeup Barrier):**
   * Проснувшийся телефон дилера обязан заблокировать локальные таймеры и сначала дождаться свежего снимка из сети, прежде чем делать любые записи в базу.
4. **Бессмертие активных столов:**
   * Столы со статусом `running` или `paused` **никогда не считаются устаревшими (stale)** и не удаляются по тайм-ауту 3.5 часов.
5. **Абсолютная чистота репозитория и непрерывный деплой:**
   * После выполнения ЛЮБОЙ задачи (как разработки, так и верификации) рабочее дерево git обязано быть чистым (`working tree clean`).
   * Изменения должны быть проверены тестами, закоммичены, отправлены в `origin main` (триггер Vercel) и сбамплены в кэше (`sw.js`). При изменении GAS-скриптов — выполнен `deploy_apps_script.js`.

## 🛠 Протокол работы Антигравити (Алгоритм выполнения одного цикла)

Каждый раз, когда пользователь отправляет управляющий промпт, Антигравити действует по следующему строгому протоколу:

1. **Инспекция состояния**:
   * Прочитать данный файл `ROADMAP.md`.
   * Найти текущую активную задачу (помеченную `[IN_PROGRESS]` или первую с меткой `[TODO]`).
2. **Исполнение задачи**:
   * Если задача типа **`[FEATURE / FIX]`**:
     - Внести минимально достаточные, высокоточные правки в код.
     - Запустить проверку линтером: `node .agent/skills/impeccable/scripts/detect.mjs --json tv/styles.css tv/tv.js dealer/styles.css dealer/dealer.js`.
     - Запустить сьют тестов: `node tests/run_all_tests.js`.
   * Если задача типа **`[VERIFY / E2E]`**:
     - Написать глубокий автоматизированный тест (при необходимости установить Playwright: `npm install -D playwright` и создать headless browser E2E-тест).
     - Протестировать граничные случаи, мокируя окружение ТВ, сбои сети или сон смартфона.
     - Добиться 100% зелёного прогона.
3. **Релиз и деплой (ОБЯЗАТЕЛЬНО)**:
   * Бампнуть версию кэша в `sw.js` (`atmos-vXX`), `tv/index.html` и `dealer/index.html` (`?v=XX.0`), `package.json`.
   * Добавить актуальную версию кэша в проверку `tests/test_performance_and_caching.js`.
   * Прогнать `node tests/run_all_tests.js` (убедиться, что ВСЕ тесты PASSED).
   * Если правились файлы Google Apps Script — запустить `node scripts/deploy_apps_script.js`.
   * Сделать `git add -A`, понятный коммит и `git push origin main`.
4. **Обновление чек-листа**:
   * Поставить `[DONE]` напротив завершённой задачи.
   * Перевести следующую задачу в статус `[IN_PROGRESS]`.
   * Сохранить обновлённый `ROADMAP.md`.
5. **Отчёт пользователю**:
   * Кратко доложить: что сделано, как проверено, номер коммита и статус деплоя. Готовность к следующему промпту.

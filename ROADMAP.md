## 📌 Архитектурный контекст и фундаментальные законы системы

### 1. Стек и инфраструктура
* **Frontend**: Vanilla JS (ES6+), CSS3 Variables, PWA / Service Worker (`sw.js`).
* **ТВ-терминал** (`tv/`): Полноэкранный HUD для Smart TV (LG webOS, Samsung Tizen, Android TV, mini-PC) в разрешении 1080p / 4K UHD.
* **Пульт ведущего** (`dealer/`): Telegram WebApp / Mobile PWA на смартфонах ведущих (iOS Safari, Android Chrome).
* **Шина синхронизации**: Firebase Realtime Database (`europe-west1`).
* **Бэкенд аналитики и лидербордов**: Google Apps Script Web App (Google Sheets).
* **Хостинг и деплой**: Vercel Production (автодеплой каждого коммита в ветку `main`).

---

### 2. ⚡ Железные архитектурные законы (Нерушимые правила!)
1. **Принцип «Единственного Писателя» (Single Writer Principle):**
   * **ТВ — это 100% пассивный терминал-отображатель.** ТВ **НИКОГДА** не мутирует Firebase (`.set()`, `.update()`).
   * Изменять состояние стола имеет право **только пульт дилера**.
2. **Детерминированное чистое время (Pure Time Math):**
   * Таймер — это чистая математическая функция от `startedAt`, `totalPausedMs` и структуры (`calculateTournamentProgress`). Никаких мутабельных гонок миллисекунд.
3. **Защита от спящего смартфона (Wakeup Barrier):**
   * Проснувшийся телефон дилера (`visibilitychange`/`focus`) блокирует отправку данных через `IS_SERVER_SYNC_PENDING`, пока не получит свежий сетевой снимок.
4. **Бессмертие активных столов:**
   * Столы `running` и `paused` никогда не считаются устаревшими (`isTableStale`) и не удаляются по тайм-ауту 3.5 часов.
5. **Абсолютная чистота репозитория и непрерывный деплой:**
   * После выполнения ЛЮБОЙ задачи (как разработки, так и верификации) рабочее дерево git обязано быть чистым (`working tree clean`).
   * Каждая задача завершается бампом версии кэша (`sw.js`, `package.json`, `index.html`), прогоном тестов, коммитом и `git push origin main`.

## 🛠 Протокол работы Антигравити (Алгоритм выполнения одного шага)

Каждый раз, когда запускается управляющий промпт, агент действует по следующему протоколу:

1. **Инспекция состояния**:
   * Прочитать данный файл `ROADMAP.md`.
   * Найти первую активную задачу со статусом `[IN_PROGRESS]` или первую со статусом `[TODO]`.
2. **Исполнение задачи**:
   * Если задача типа **`[FIX / FEATURE]`**:
     - Внести высокоточные правки в код (соблюдая принципы Impeccable и архитектурные законы).
     - Проверить линтером дизайна: `node .agent/skills/impeccable/scripts/detect.mjs --json tv/styles.css tv/tv.js dealer/styles.css dealer/dealer.js` (строго `[]`).
     - Прогнать мастер-тест: `node tests/run_all_tests.js`.
   * Если задача типа **`[VERIFY / E2E]`**:
     - Написать/обновить глубокий Playwright E2E тест (`tests/test_e2e_*.js`).
     - Запустить headless-браузер (Chromium/Edge), снять контрольные скриншоты в `tests/screenshots/`.
     - Проверить физические размеры элементов (через `boundingBox()`), контрастность, отсутствие наложений и переполнений текста.
     - Добиться 100% зелёного прогона.
3. **Релиз и деплой (ОБЯЗАТЕЛЬНО)**:
   * Бампнуть версию кэша в `sw.js` (`atmos-vXX`), `tv/index.html` и `dealer/index.html` (`?v=XX.0`), `package.json`.
   * Добавить актуальную версию кэша в `tests/test_performance_and_caching.js`.
   * Запустить `node tests/run_all_tests.js` (убедиться, что ВСЕ тесты PASSED).
   * Сделать `git add -A`, понятный коммит и `git push origin main`. Убедиться в `working tree clean`.
4. **Обновление чек-листа**:
   * Поставить `[DONE]` напротив завершённой задачи.
   * Перевести следующую задачу в статус `[IN_PROGRESS]`.
   * Сохранить обновлённый `ROADMAP.md`.
5. **Отчёт пользователю**:
   * Кратко доложить: номер закрытой задачи, что сделано/проверено, хэш коммита на GitHub, статус тестов и деплоя, и какая задача стоит следующей.

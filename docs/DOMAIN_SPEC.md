# Каноническая доменная спецификация Atmosphere Poker Club
> **Статус:** Канонический эталон (Source of Truth)  
> **Назначение:** Обязательный справочник бизнес-логики, контрактов данных, правил игры и стандартов тестирования для разработчиков и автономных AI-сабагентов.

---

## 1. Архитектура системы

Система покерного клуба «Атмосфера» состоит из 4 ключевых компонентов:
1. **ТВ-экран трансляции в зале (`/tv`):**
   - Роль: Пассивный широкоформатный спектэйтор (Display Only).
   - Отображает от 1 до 4 активных столов в реальном времени (16:9 бродкаст-кокпит Triton/EPT).
   - В режиме 3 столов 4-й квадрант занимает **Live Club Leaderboard Hub** с плавной ротацией 3 экранов:
     - Слайд 1: 🏆 Топ месяца
     - Слайд 2: 🌟 Топ за всё время
     - Слайд 3: 🔥 Последние победители (из `data.hof` по `place === 1`)
   - **Автопрогрессия уровней в зале:** Если телефон ведущего уснул, экран ТВ при наступлении `levelEndsAt` в статусе `running` автономно переключает раунд стола в Firebase.
   - **Аппаратная защита от засыпания (Anti-Sleep):** Микро-видеопоток 1 FPS Canvas (`#tv-wake-video`) + циклический авто-перезапрос `navigator.wakeLock` каждые 3 минуты.
   - **Скрытый тестовый режим:** 4 быстрых тапа по шапке/логотипу открывают `#tv-sim-toolbar` (1–4 стола, перерыв, алерт, сброс в Live) с персистентностью в `localStorage` и `#mock=...`.

2. **Пульт ведущего турнира (`/dealer`):**
   - Роль: Одноручный мобильный пульт управления конкретным столом (Dealer Cockpit).
   - Доступ: Строгий белый список Telegram (`@atmosphere_poker_dealer_bot`). Никаких мастер-PIN-кодов!
   - Ключевые действия: Старт турнира, Пауза/Возобновление (большая кнопка под большой палец), Быстрый переход уровня (`⏩`) с плавающим 3-секундным снекбаром отмены (`↩️ Отменить`), тонкая коррекция времени `[ -1 мин ]` / `[ +1 мин ]`, выбывание игроков, перерывы, завершение игры с защищенным диалогом подтверждения.
   - **Скрытый тестовый режим пульта:** 4 быстрых тапа по шапке открывают оффлайн-песочницу пульта (`DEALER_SIMULATION_MODE`), позволяющую безопасно тестировать любые кнопки без мутации базы данных.

3. **Облачная база данных (Firebase Realtime Database):**
   - Узел `/atmosphere/tables/{dealerId}` — состояние каждого стола в реальном времени.
   - Узел `/atmosphere/mtt_session` — координация многостоловых турниров (MTT).
   - Узел `/atmosphere/dealers_registry` — защищенный справочник авторизованных ведущих.
   - Системный узел `/.info/serverTimeOffset` — авто-компенсация рассинхрона часов между устройствами.

4. **Пайплайн результатов, Google Таблицы и Telegram (`Code.js`, `Normalizer.js`, `TelegramNotifier.js`):**
   - После окончания игры ведущий отправляет Google-форму с результатами.
   - Триггер `processFormSubmit` нормализует имена, даты, рассчитывает очки, записывает участников в `DB_Results`, обновляет кэш аналитики и отправляет победный пост в Telegram-канал клуба.
   - **Подсчёт игр за день:** Персональный счётчик конкретного ведущего (`(X-я игра у ведущего за сегодня)`) с поддержкой ночного покерного окна (до 06:00 утра игры относятся к вчерашнему турнирному вечеру).

## 2. Жизненный цикл и State Machine стола

Стол ведущего может находиться в одном из следующих строгих состояний (`status`):

| Статус | Описание | Допустимые переходы | Инварианты |
|---|---|---|---|
| `idle` | Стол свободен / готов к настройке | ➔ `running`, `lobby` | Таймер сброшен, `levelEndsAt = null`, `remainingMs = durationSec * 1000`. |
| `running` | Идёт уровень турнира | ➔ `paused`, `break`, `finished` | `levelEndsAt = now + remainingMs`. Таймер тикает каждую секунду. При наступлении `now >= levelEndsAt` происходит автопереход на следующий уровень. |
| `paused` | Игра на паузе (техническая пауза) | ➔ `running`, `finished` | `levelEndsAt = null`. В `remainingMs` зафиксирован точный остаток секунд на момент паузы. |
| `break` | Официальный перерыв турнира | ➔ `running`, `finished` | `isBreakActive = true`, `breakEndsAt = now + breakDurationSec * 1000`. По истечении времени переходит в овертайм (`+MM:SS`). |
| `finished`| Игра завершена, переход в Post-Game | ➔ `idle` (сброс стола) | Блайнды скрываются, предлагается форма отправки результатов и перерыв перед следующей игрой. |
| `lobby` | Сбор столов для турнира МТТ | ➔ `running`, `idle` | Головной стол ожидает подключения столов-сателлитов. |
| `ready` | Сателлит готов к общему старту МТТ | ➔ `running`, `idle` | Сателлит ожидает широковещательного старта от головного стола. |

### Защита монотонности уровней (Monotonic Level Guard)
- **Правило:** При пробуждении телефона дилера (`visibilitychange` / `window.focus`), если состояние стола на сервере имеет `remote.levelIndex > local.levelIndex`, телефон **обязан** безоговорочно принять состояние сервера и сбросить устаревшие локальные оптимистичные обновления. Откат уровня назад категорически запрещён!

## 3. Покерные структуры и правила клуба

В клубе «Атмосфера» проводятся спортивные турниры без денежных выплат:
1. **SnG (Sit & Go):**
   - Стартовый стек: 5 000 фишек (100 BB).
   - Длительность уровней: 7 минут (420 сек). Целевое время турнира: 70–80 минут.
   - Расписание блайндов:
     1. 25 / 50 (Анте 0)
     2. 50 / 100 (Анте 0)
     3. 75 / 150 (Анте 0)
     4. 100 / 200 (Анте 200)
     5. 150 / 300 (Анте 300)
     6. 200 / 400 (Анте 400)
     7. 300 / 600 (Анте 600)
     8. 400 / 800 (Анте 800)
     9. 600 / 1200 (Анте 1200)
     10. 800 / 1600 (Анте 1600)
2. **Big Blind Ante (BBA):**
   - Начиная с 4 уровня (100/200), игрок на позиции большого блайнда вносит единое анте за весь стол.
   - Размер анте равен текущему большому блайнду (`BB`).
   - На экране анте отображается второй строкой монументальным золотым шрифтом (`АНТЕ 400`). Никаких рамок, плашек и ромбиков!
3. **Ликвидация Color-Up:**
   - Понятие Color-Up и технические паузы размена фишек полностью исключены из системы. Уровни сменяются непрерывно.
4. **Окно турнирного вечера (Midnight Session Rollover):**
   - Игровой вечер клуба длится до поздней ночи. Любые игры, завершившиеся после полуночи до 06:00 утра, считаются продолжением вчерашнего турнирного вечера.

## 5. Правила безопасности и изоляции тестов

1. **Строгий запрет утечек в продакшн:**
   - Любой файл автотеста обязан подключать `tests/network_guard.js`.
   - Запросы к `firebasedatabase.app`, `firebaseio.com` и `api.telegram.org` перехватываются in-memory.
2. **Отсутствие хардкода секретов:**
   - Никаких мастер-паролей ("7777") в кодовой базе.
   - Токены ботов читаются строго из переменных окружения или скриптовых свойств.
3. **Запрет моковых тавтологий:**
   - Тесты не должны создавать искусственный объект и проверять равенство его полей самим себе. Тесты обязаны вызывать реальные функции из `tv/tv.js`, `dealer/dealer.js`, `Config.js`, `Normalizer.js`.

## 6. Стандарт промпта для сабагентов (Subagent Task Blueprint)

При постановке задач на разработку или тестирование сабагент обязан получать задание в формате BDD:

```markdown
### КОНТЕКСТ ЗАДАЧИ
- Компонент: [dealer / tv / pipeline / api]
- Ссылка на спецификацию: DOMAIN_SPEC.md #[Раздел]

### ТРЕБОВАНИЯ (GIVEN - WHEN - THEN)
- **GIVEN**: Исходное состояние системы (например, стол в статусе running на 5 уровне с remainingMs = 200с).
- **WHEN**: Происходящее событие (например, ведущий нажимает "+1 мин" или телефон засыпает на 450 секунд).
- **THEN**: Ожидаемое состояние системы (например, remainingMs увеличивается на 60с, Firebase обновляется; или серверный уровень принимается без отката).

### СТРОГИЕ ОГРАНИЧЕНИЯ (ANTI-PATTERNS)
- ❌ НЕ создавать тавтологичных проверок (assert.ok(true)).
- ❌ НЕ вызывать боевые сетевые адреса без network_guard.js.
- ❌ НЕ хардкодить старые моковые имена ("Владимир Т.", "Александр М.").
- ✅ ОБЯЗАТЕЛЬНО запускать локальный прогон и линтер перед сдачей отчета.
```

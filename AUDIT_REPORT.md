## РЕЗЮМЕ АУДИТА (EXECUTIVE SUMMARY)

Покерная экосистема антикафе «Атмосфера» представляет собой распределенную систему реального времени, сочетающую:
- **Serverless Edge Frontend на Vercel** (статические веб-приложения пульта дилера и ТВ-экрана + Node.js функции);
- **Firebase Realtime Database** в качестве высокоскоростной шины синхронизации состояния между планшетами дилеров и телевизорами зала;
- **Google Sheets & Google Apps Script** в качестве долгосрочной реляционной базы данных турниров, профилей игроков и движка агрегации сезонных лидербордов;
- **Telegram Bot API** для авторизации персонала и уведомлений об итогах игр.

В ходе всестороннего аудита кодовой базы выявлены критические проблемы безопасности, архитектурные конфликты «Split-Brain» и прямая причина спонтанного оживания столов («призрачных игр»). Ниже представлены детальные отчеты по четырем обязательным разделам.

### 1.1. Отсутствие `package.json` и неконтролируемые зависимости
В корневом каталоге проекта полностью **отсутствует файл `package.json`**. 
- Проект использует гибридный рантайм: Node.js (для тестов в `tests/`, служебных скриптов в `scripts/` и Serverless Functions в `api/`), Google Apps Script (движок V8 в облаке Google) и браузерный Vanilla JS.

### 3.2. Рассинхронизация времени таймера (Clock Drift)
Таймер в экосистеме вычисляется децентрализованно:
- На пульте дилера (`dealer.js:929`):
  `table.levelEndsAt = Date.now() + table.remainingMs;` (время берется с системных часов смартфона дилера).
- На ТВ-экране (`tv.js:419`):
  `remaining = Math.ceil((table.levelEndsAt - Date.now()) / 1000);` (время берется с часов ТВ/ПК).

**Проблема:**  
Если часы на телефоне дилера спешат на 20 секунд относительно часов ПК телевизора:
1. Дилер видит `00:00`, нажимает «Следующий уровень».
2. На ТВ в этот момент отображалось `00:20`. Экран внезапно «перепрыгивает» на следующий уровень за 20 секунд до конца блайндов.
3. И наоборот: если часы ТВ спешат, ТВ входит в овертайм, проигрывает гонг и пятисекундный звуковой отсчет раньше времени, сбивая игроков с толку.

В системе **не используется встроенный механизм Firebase `/.info/serverTimeOffset`**, позволяющий синхронизировать клиентские часы с атомными часами серверов Google.

### 3.3. Архитектурный конфликт «Split-Brain» при смене уровней
И на пульте дилера, и на экране ТВ **одновременно** реализована логика автоматического переключения уровней:
- В пульте: `dealer.js:1973` (`checkAutoLevelProgression()`).
- На ТВ: `tv.js:1541` (`syncTableAutoProgression()`).

Когда время уровня истекает:
1. И телевизор, и смартфон дилера одновременно фиксируют `Date.now() >= table.levelEndsAt`.
2. Телевизор отправляет в Firebase `PATCH` с инкрементом `levelIndex + 1`.
3. Пульт дилера отправляет в Firebase `PUT` со своим инкрементом `levelIndex + 1`.
4. Если одно из устройств успевает прочитать запись другого до отправки своей, **происходит двойной инкремент уровня** — турнир перепрыгивает через уровень блайндов.

> **Важнейшее правило архитектуры:** Телевизор (дисплей) обязан быть **пассивным клиентом-читателем (Pure Consumer)**. Дисплей ни при каких обстоятельствах не должен производить запись бизнес-состояний в базу данных за столы, управляемые дилером!

### 3.4. Избыточный транспорт: Дублирование WebSocket и REST Polling
В `tv.js` и `dealer.js` параллельно активны два канала получения данных:
1. Постоянный WebSocket через Firebase SDK (`.on("value")`).
2. Функция `startRestPollingFallback`, которая **каждые 1500 мс** делает HTTP GET запросы к `/atmosphere/tables.json` и `/atmosphere/mtt_session.json`.

При устойчивом интернет-соединении это создает постоянную паразитную нагрузку на канал и провоцирует гонки обновлений между быстрым сокетом и запаздывающим REST-ответом.

### 3.5. Утечки памяти и «DOM-шторм» при длительной трансляции на ТВ
Телевизор в клубе работает непрерывно по 10–14 часов. При этом в `tv.js`:
- Основной цикл рендера вызывается по таймеру каждые **250 миллисекунд** (`setInterval(renderTables, 250)`).
- В строке `tv.js:1513` проверяется флаг перерыва:
  ```javascript
  const isBreakScreen = (table.isBreakActive && table.breakEndsAt > Date.now()) || ...;
  if (isBreakScreen) {
    canPatchDom = false;
    break;
  }
  ```
- Когда хотя бы один стол уходит на перерыв (или перерыв между играми), флаг `canPatchDom` сбрасывается в `false` на **каждом тике**.
- В результате **4 раза в секунду** вызывается полная перезапись DOM:
  `viewport.innerHTML = buildFullTablesHtml(...)`.
- Браузер Smart TV 4 раза в секунду уничтожает сотни DOM-узлов, пересчитывает стили, верстку и пересоздает структуру экрана. Это приводит к колоссальной нагрузке на Garbage Collector, микрофризам анимаций и прогрессирующей утечке памяти Chromium/WebKit.

### Детализация реализации Quick Wins:

#### 1. Сетевой барьер для тестов (`tests/network_guard.js`)
Создать единый мок, подключаемый во все тесты или принудительно перехватывающий сетевые вызовы Node.js:
```javascript
// Защита от случайных боевых сетевых вызовов в тестах
if (typeof global.fetch === "function") {
  const originalFetch = global.fetch;
  global.fetch = async (url, options) => {
    if (typeof url === "string" && url.includes("firebasedatabase.app")) {
      // Возвращаем успешный ответ-заглушку без реального сетевого сокета
      return { ok: true, json: async () => ({}), text: async () => "{}" };
    }
    return originalFetch(url, options);
  };
}
```

#### 2. Базовые правила безопасности Firebase (`database.rules.json`)
```json
{
  "rules": {
    "atmosphere": {
      "tables": {
        ".read": true,
        "$tableId": {
          ".write": "newData.hasChildren(['status', 'levelIndex'])",
          ".validate": "newData.child('status').val().matches(/^(idle|ready|lobby|running|paused|finished)$/)"
        }
      },
      "mtt_session": {
        ".read": true,
        ".write": true
      },
      "dealers_registry": {
        ".read": true,
        ".write": false
      }
    }
  }
}
```

#### 3. Удаление утечки PIN-кода
В `api/dealer-bot.js:125` заменить текст отказа для неавторизованных пользователей на нейтральный:
```javascript
const deniedText = "🔒 <b>Доступ ограничен</b>\n\n" +
  "Ваш аккаунт @" + escapeHtml(username || "не_задан") + " не зарегистрирован в списке ведущих клуба «Атмосфера».\n" +
  "Для получения доступа обратитесь к старшему администратору.";
```

#### 4. Синхронизация времени по `serverTimeOffset`
Подключить во фронтенде смещение часов:
```javascript
let SERVER_TIME_OFFSET = 0;
firebase.database().ref(".info/serverTimeOffset").on("value", (snap) => {
  SERVER_TIME_OFFSET = snap.val() || 0;
});
function getSyncedNow() {
  return Date.now() + SERVER_TIME_OFFSET;
}
```
И заменить `Date.now()` в расчетах таймера на `getSyncedNow()`.

#### 5. Точечный патчинг экрана перерыва на ТВ
Вместо полной перерисовки через `innerHTML` обновлять только текстовые поля таймера перерыва (`card.querySelector('.break-timer-val').textContent = ...`), сохраняя `canPatchDom = true`.

## ЗАКЛЮЧЕНИЕ

Кодовая база обладает продуманной компоновкой стилей и удобным интерфейсом для дилеров и зрителей. Однако текущие уязвимости безопасности и архитектурные наложения (мутация базы тестами и одновременное управление турниром с телевизора и пульта) являлись главным источником нестабильности. Внедрение **Топ-5 быстрых побед** переведет экосистему на уровень стабильного коммерческого продукта.
